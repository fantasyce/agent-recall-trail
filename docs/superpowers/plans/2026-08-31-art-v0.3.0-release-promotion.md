# ART 0.3.0 Release and Promotion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Validate, publish, install, and promote ART 0.3.0 only after the progressive recall foundation and optional embedding adapter pass source, packaged, installed, live Codex, and live DSH acceptance.

**Architecture:** Release acceptance follows `source -> release assets -> installed runtime -> live MCP hosts -> public release`. Formal private ART data stays outside the public repository; release and promotion use aggregate evidence and public product material only.

**Tech Stack:** Cargo release builds, Git/GitHub CLI, MCP stdio, local Codex, local DSH, shell release gates, static ART site

**Spec:** `docs/superpowers/specs/2026-08-31-art-progressive-recall-architecture-design.md`

## Global Constraints

- Do not publish until every required gate passes on the final bytes.
- Do not include local memories, Knowledge Editions, vectors, endpoint files, credentials, private paths, test datasets, or raw benchmark runs in Git or release assets.
- Install only the exact verified public release artifact into the formal local runtime.
- Keep embedding unconfigured by default; a configured provider is optional and provider quality is not an ART core release claim.
- Real Codex and DSH acceptance must prove route, lexical, full scan, exact read, private isolation, and shared knowledge recall.
- Clean only task-owned residue; preserve formal private ART data and any separately owned embedding service.
- Promotion claims must match final acceptance evidence and public artifacts.
