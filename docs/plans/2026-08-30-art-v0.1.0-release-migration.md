# ART v0.1.0 Release and Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish ART v0.1.0, migrate the complete local KnowledgeBase into reviewed ART Knowledge Editions, install ART for Codex and validate DSH, then remove Basic Memory after a proven cutover.

**Architecture:** Markdown migration uses exact `FileSnapshot` source locks and the existing human review/publish state machine; it never converts shared knowledge into private Agent memory. The release packages one native stdio runtime plus a thin Codex plugin and uses the ARE/ARP public launch surfaces. Destructive cleanup is the final gate and targets only the pre-inventoried Basic Memory paths.

**Tech Stack:** Rust 1.98, SQLite/FTS5, RMCP stdio, Clap, shell, GitHub Actions, GitHub Pages, Codex plugins, DSH overlays, MCP Registry metadata

**Spec:** `docs/specs/2026-08-30-art-v0.1.0-release-migration-design.md`

## Global Constraints

- Stable version is exactly `0.1.0`; release tag is exactly `v0.1.0`.
- Keep per-Agent private SQLite files and shared Knowledge Editions as separate authorities.
- Agents cannot approve or publish knowledge through MCP.
- Tests must use `/tmp/art-v0.1.0-release-migration-20260830` or another explicit task-owned ART home, never formal data.
- Do not change or delete the old KnowledgeBase until formal migration reconciliation and real Codex/DSH recall pass.
- Do not publish secrets, private knowledge, migration bodies, machine paths, or host credentials.
- The public release may include code, schemas, synthetic fixtures, redacted acceptance summaries, and launch copy only.
