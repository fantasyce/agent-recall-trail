# ART v0.1.0 Release, Migration, and Replacement Design

**Date:** 2026-08-30
**Status:** Approved by the user's 2026-08-30 execution request

## Goal

Release ART v0.1.0 as an independent open-source product, install it as the
local Codex memory-and-knowledge plugin, migrate every eligible document from
the existing private KnowledgeBase into reviewed ART Knowledge Editions, prove
the released runtime with real Codex and DSH sessions, and only then remove the
local Basic Memory runtime and its historical local directories.

## Release identity

The stable version is `0.1.0`, following `0.1.0-rc.1`. The public repository is
`fantasyce/agent-recall-trail`; the release tag is `v0.1.0`. The tag must point
to the tested `origin/main` commit. Publication must include native release
archives, checksums, an SPDX SBOM, source provenance, a thin Codex plugin, MCP
Registry metadata, a dependency-free project site, and launch material.

## Migration model

Migration preserves ART's two-authority architecture:

- Existing Markdown documents are external file snapshots, not private Agent
  memories.
- Each eligible Markdown file becomes one proposal with an exact relative
  source identifier, SHA-256 content lock, title, applicability, and immutable
  draft body.
- The local operator reviews and approves each exact proposal revision, then
  publishes one immutable Knowledge Edition. Agents cannot invoke approval or
  publication through MCP.
- The source Markdown body is preserved byte-for-byte as the Edition body.
  Basic Memory-specific frontmatter and wiki links remain readable and
  searchable; they are not treated as ART authority metadata.
- A machine-readable migration receipt maps every source path and digest to
  its proposal and Edition. It records blocked files separately and fails the
  cutover unless all expected Markdown files are published and hash-valid.

The old KnowledgeBase remains unchanged throughout staging and acceptance.
Its private Git remote is verified before local deletion and is retained as an
off-machine disaster-recovery copy; deleting that remote repository is outside
this local uninstall.

## Formal runtime

ART runtime data stays under `~/.across`:

- binary: `~/.across/bin/art`;
- configuration: `~/.across/config/art/config.json`;
- data: `~/.across/data/art`;
- logs and migration receipts: `~/.across/logs/art`.

A user-owned `~/.local/bin/art` symlink makes the binary discoverable to local
Agent hosts while keeping executable bytes under `~/.across`. The Codex plugin
contains a skill and stdio MCP declaration using `art mcp serve --agent
codex-primary`. DSH acceptance uses the same installed binary with a bound
`dsh-primary` identity and an isolated overlay. ART is not a daemon; host-owned
stdio children exit with their sessions.

## Codex replacement boundary

Cutover is ordered and reversible:

1. Install and validate ART alongside Basic Memory without changing the old
   canonical source.
2. Publish and verify all Knowledge Editions in the formal ART home.
3. Start new Codex and DSH sessions against the installed ART binary and prove
   private capture/recall, cross-Agent denial, shared knowledge recall, and
   health/reconnect behavior.
4. Remove the `basic-memory` MCP entry, install and enable the ART Codex plugin,
   and verify a new Codex session sees ART tools and migrated knowledge.
5. Stop verified Basic Memory stdio children, uninstall the uv tool, remove its
   stale Codex skill, and delete only the inventoried local Basic Memory paths.
6. Re-run ART Doctor, migration reconciliation, Codex/DSH recall, process, path,
   and Codex configuration checks after deletion.

Rollback before step 5 restores the saved Codex configuration and leaves the
old KnowledgeBase intact. After step 5, the verified private Git remote and
the migration receipt provide recovery inputs; ART remains the active local
authority.

## Acceptance contract

Release and cutover pass only when all of the following are fresh and green:

- all workspace tests and the release gate pass on the final stable commit;
- plugin, package, site, Registry, secret, license, and version-consistency
  checks pass;
- every source Markdown file is represented by exactly one current, readable,
  hash-valid Knowledge Edition, with no blocked or missing item;
- representative Chinese and English queries recover the expected migrated
  Editions from both Codex and DSH;
- Codex and DSH private memories remain physically separated and exact
  cross-Agent private reads return the uniform not-found result;
- the installed binary digest matches the published release asset;
- the ART plugin is installed and enabled, `basic-memory` is absent from the
  Codex MCP list, and a new host session uses ART;
- the Basic Memory executable, uv environment, local database/cache root,
  legacy skill, old KnowledgeBase directory, and Basic Memory processes are
  absent;
- ART data, the installed plugin, the public source checkout, and explicit
  release evidence are intentionally retained and healthy.

## Promotion model

ART follows the durable ARE/ARP launch pattern:

- public GitHub repository, protected `main`, pull request, required CI, stable
  Release, Pages site, repository topics, homepage, Discussions launch post,
  and a design-partner Issue;
- official MCP Registry metadata and publication workflow tied to the exact
  successful release commit;
- launch article, FAQ, community posts, maintainer outreach, showcase copy,
  and a machine-readable launch manifest;
- prepared copy for external authenticated communities. As with ARE/ARP, no
  unrelated social account is created and no account-scoped post is made where
  the required account surface is unavailable to this task.

## Product-site direction

The site serves developers choosing a local memory boundary. Its single job is
to make ART's separation legible: a private Agent trail on the left, a reviewed
knowledge spine in the center, and multiple Agent recall lanes on the right.
The palette uses `Ink #17202A`, `Paper #F6F8F5`, `Trail #C85D3A`, `Review
#2F6B5F`, and `Rule #CAD2CC`. The signature element is a provenance trail that
visibly changes from private dashed segments to a solid reviewed Edition,
rather than a generic feature-card grid. Typography uses local system faces
only so the page has no external runtime dependency or tracking surface.

## Explicit limits

ART v0.1.0 still does not claim hostile same-user filesystem isolation,
automatic knowledge approval, cloud replication, embeddings, HTTP MCP, AAA
integration, or a production cross-Agent broker. These documented limits do
not block the standalone Codex/DSH release.
